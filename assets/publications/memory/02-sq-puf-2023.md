## Problem and motivation

Strong Arbiter PUFs offer many challenge–response pairs and are attractive for low-cost device authentication. Their weakness is a learnable correlation: shared delay paths create a decision boundary that logistic regression or neural networks can reconstruct from observed CRPs. Earlier proposals attempted to hide either challenges or responses through XOR, random inversion, obfuscation, or multiple PUF instances, but later attacks often recovered their structure.

SQ-PUF seeks a lightweight alternative for IoT devices. Instead of relying only on a more complex static PUF, it makes the mapping depend on time/order. A captured challenge cannot be interpreted correctly without the preceding challenge state and the random transformation applied by the client.

## Core technical idea

The architecture combines:

- one Arbiter PUF rather than many parallel instances;
- an LFSR that derives the sequence of sub-challenges needed for a multi-bit response;
- a true random-number source;
- SQ modules placed on selected challenge-bit paths;
- server-side enrollment and prediction logic that knows which input positions contain SQ modules.

The SQ modules modify selected challenge bits using the previous challenge/state and a random choice. The current authentication therefore depends on the sequence, not just the current transmitted challenge. The server retains the prior accepted challenge (`C_old` in the algorithm) and simulates both possible transformations associated with the random bit. It predicts both candidate responses and accepts the received response if at least one is within a small Hamming-distance tolerance.

The first response in a new sequence is treated as initialization rather than as an independently authenticated sample. After a successful session, the server stores the new challenge for use as state in the following session.

This design intends to conceal the Arbiter-PUF separating hyperplane from an attacker while still letting an enrolled server reconstruct the two legitimate candidates.

## Enrollment and deployment model

In enrollment, the SQ path can be bypassed so the server obtains plain Arbiter-PUF CRPs and trains an accurate local model. It also records the placement of SQ modules. In deployment, selected input bits are transformed, direct access to plain behavior is no longer available, and the server uses its enrolled model plus sequence state to authenticate.

The attacker is assumed not to know the PUF’s internal structure. This assumption is important: the paper’s security argument is based on hiding the usable correlation through sequence dependence and randomization rather than on a formal secret-key protocol proof.

## Experimental method

The authors modeled a 64-stage Arbiter PUF in HSPICE and ran 1,000 Monte Carlo simulations to characterize process-dependent path delays. The reported worst-case fitted delay distribution has a mean of 52.3 ps and a standard deviation of 11 ps. Further attacks and PUF-instance experiments were run on generated CRP datasets.

The principal attack-resistance study used an ANN with four layers containing 200, 100, 80, and 64 neurons, ReLU in hidden layers, and a sigmoid output. It was trained with 500,000 samples while varying the percentage of input bits protected by SQ modules. The selected comparison configuration attaches SQ modules to 80% of the 32 challenge positions, or 25 of 32 bits.

The paper additionally compares logistic regression, ANN, and SVM attacks and evaluates uniformity, uniqueness, and component-level hardware overhead.

## Key quantitative findings

- With no SQ modules, the tested ANN modeled the PUF with 98.16% accuracy.
- Adding SQ modules to only 10% of the 32 input bits—three bits—reduced ANN accuracy to 74.16%, an improvement of about 24 percentage points against that attack.
- In the main comparison using 400,000 CRPs, SQ-PUF attack accuracy was 52.14% for logistic regression and 52.4% for the ANN. The reported SVM accuracy was 50.22%.
- The paper summarizes the strongest tested ANN prediction as not exceeding about 53%, close to binary random guessing.
- For 64-bit challenges and responses over 20,000 CRPs, reported SQ-PUF uniformity was 50.561% and uniqueness was 49.101%, close to their ideal values of 50%.
- The hardware table reports 34 LUTs and 64 flip-flops for the LFSR, 128 LUTs and one flip-flop for the 64-stage one-bit Arbiter PUF, and one LUT plus one flip-flop per SQ module. This is component accounting, not a technology-independent total-area guarantee.

## What is novel

The paper moves the defense from a static challenge/result transformation to sequence dependence. A model trained on isolated CRPs lacks the temporal context required to reconstruct the client’s effective input. The SQ module is deliberately small and can be applied selectively, exposing a tunable security/area trade-off. A single LFSR and Arbiter PUF generate multi-bit responses serially, reducing hardware relative to designs that duplicate the PUF for every response bit.

## Limits and non-claims

- The evidence is empirical and restricted to the implemented LR, ANN, and SVM attacks. It does not prove security against every modeling or protocol attack.
- The delay and PUF behavior are based primarily on HSPICE/Monte Carlo and generated datasets in the reported evaluation. Do not describe the paper as a broad post-silicon validation unless separate evidence is supplied.
- The server must enroll the device securely, retain the trained PUF model and sequence state, know SQ-module placement, and remain synchronized with the client.
- The threat model assumes the attacker lacks internal structural knowledge. Invasive reverse engineering, server compromise, state rollback, desynchronization, and arbitrary active-channel attacks are not comprehensively proven away.
- “Approximately 53% attack accuracy” refers to the tested binary prediction tasks and should be phrased as near random guessing in that setup, not absolute immunity.
- The English title is a normalized translation used by the author’s CV. The source paper itself is Persian.
